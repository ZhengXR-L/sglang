# GLM-5.2 HiCache 布局 TTFT 对比

比较 layer_first_kv_split 与 page_first_kv_split 的实际服务路径，D2H/H2D 均显式选择 AIV。

固定 TP8/EP8、并发 1；同一组 NPU，按 layer/page/page/layer 顺序。

每场景输入为目标前缀长度 +128 token；A 重算，B=2816 token 驱逐，R 原输入回迁。A/R 输出32 token，B输出8 token，temperature=0、ignore_eos=true。

每种长度每次服务先预热一轮（i0，不计时统计），再测五轮。TTFT 从请求发送到首个含 output_ids 的事件；同时保存首个非空文本时间。

强制 A 无缓存、R 的 L1=0 且 L2 命中至少 128 token、A/R 均包含题目正确数值；逐 token 相同率另行记录。任一失败中止该次比较。

不加载逐调用 event/JSONL audit hook。使用 warning 日志，双方禁用 AIV trace；计时没有逐层日志 I/O。缓存写入可能与计算重叠，A TTFT 不等于 D2H 总耗时，R TTFT 也不等于纯算子耗时。
